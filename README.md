# HTMLMemo

웹 페이지를 HTML 한 파일로 보관하고, 저장한 문서와 로컬 HTML에 주석을 남기는 독립 PWA입니다. 모든 문서·주석·설정은 기기 안에만 저장합니다. GitHub Pages는 설치할 앱의 정적 코드만 제공합니다. 데이터 저장용 서버·로그인·API 키는 사용하지 않습니다.

## 설치와 URL 공유

**이 앱은 구글 크롬에서만 정상적으로 작동합니다. 크롬에서 실행해주세요.**

전용 저장 폴더를 지원하는 최신 Google Chrome에서 같은 URL을 엽니다. 폴더 선택 API 또는 안전한 폴더 쓰기에 필요한 기능이 없으면 Chrome 실행 안내가 표시되며 서재로 넘어가지 않습니다. 안내에서 앱 주소를 복사할 수 있고 복사 권한이 없으면 주소를 직접 선택해 복사합니다. iPhone·iPad처럼 Chrome에서도 전용 폴더 연결을 제공하지 않는 환경은 지원 대상이 아닙니다. [폴더 선택 API와 기능 확인](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access#feature-detection).

1. Google Chrome으로 https://seionwon.github.io/HTMLMemo/ 를 엽니다. 추가 설치·연결 설정은 필요하지 않습니다.
2. **HTML 파일 가져오기**, 메뉴의 **텍스트 붙여넣기**, 주소창의 **웹 페이지 열기**로 시작합니다.
3. 홈 화면에 아이콘이 필요할 때만 **앱 설치**를 선택합니다. 처음 로딩과 오프라인 준비를 마친 뒤에는 저장한 HTML을 오프라인으로 사용할 수 있습니다. 웹 탐색에는 인터넷이 필요합니다. [MDN 설치 기능](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

다른 사람에게는 **https://seionwon.github.io/HTMLMemo/** 주소만 보냅니다. 앱 내부의 **실행 → URL 복사**로 복사하거나 표시된 주소를 직접 선택해 복사할 수 있습니다. 복사 권한이 없으면 주소를 선택하는 안내를 표시하고 버튼을 다시 사용할 수 있게 복구합니다. 앱 전달용 ZIP과 설치 안내 HTML을 만들지 않습니다. 문서·주석·설정은 공유 URL에 포함되지 않으며 받은 사람의 데이터도 자신의 기기에 저장됩니다.

## GitHub Pages 자동 배포 · seionwon/HTMLMemo

배포 절차는 **프로젝트 소스를 main에 저장 → GitHub Actions가 검사·빌드 → GitHub Pages 게시**입니다. 앱 사용자는 주소만 받습니다. 앱 빌드는 이 저장소의 public/, scripts/, package.json, package-lock.json을 사용하고 tests/와 .github/workflows/deploy-pages.yml로 검증·게시합니다. 예전 extension/ 소스는 배포하지 않습니다.

1. [seionwon/HTMLMemo](https://github.com/seionwon/HTMLMemo)에 프로젝트 소스와 **.github/workflows/deploy-pages.yml**을 main 브랜치로 저장합니다.
2. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다. 기존에 main /docs로 설정했다면 GitHub Actions로 변경합니다.
3. **Actions → Deploy HTMLMemo to GitHub Pages → Run workflow**를 누릅니다. 이후 main 브랜치의 변경은 자동으로 배포를 실행합니다.
4. 검사·빌드·배포가 모두 성공하면 **Settings → Pages → Visit site**에서 게시 주소를 확인합니다. 기본 주소는 https://seionwon.github.io/HTMLMemo/ 입니다.
5. 사이트에서 앱 설치, 로컬 HTML 가져오기와 주석, 설정 JSON 저장·복원, 설치 후 오프라인 읽기를 확인합니다.

워크플로는 npm ci, npm test, npm run check, npm run build를 실행하고 **dist/만** GitHub Pages에 게시합니다. 개인 문서·설정·첨부·개발 의존성은 웹 빌드에 포함하지 않습니다. 검사나 빌드가 실패하면 배포 작업을 실행하지 않습니다. 앱 코드 또는 연결 기능의 코드가 바뀌면 오프라인 캐시 버전도 변경하며 기기의 문서 저장소는 지우지 않습니다.

GitHub Pages의 Source 설정과 실제 사이트 게시가 완료되어야 주소를 다른 사용자에게 전달할 수 있습니다. 2026-10-13에는 사용자가 선택한 라이브러리 데스크 디자인을 `84a6de7`로 main에 push하고 GitHub Actions·Pages 게시 성공을 확인했습니다. 게시된 HTML·CSS·아이콘·manifest·앱 JavaScript가 로컬 빌드와 일치함도 검증했습니다. 로컬 빌드 성공만으로 실제 게시 완료를 표시하지 않습니다. [GitHub Actions를 통한 Pages 배포](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## GitHub 게시 인증

앱 사용과 Actions 배포에는 앱에 입력할 API 키가 필요 없습니다. Actions는 GitHub가 제공하는 GITHUB_TOKEN을 사용하며 사용자 문서와 설정을 읽지 않습니다. 프로젝트 소스를 GitHub에 올리는 개발 도구는 저장소에 쓰기 권한이 있는 계정으로 로그인해야 합니다.

API로 소스와 워크플로를 업로드할 경우에만 fine-grained 토큰을 준비합니다.

1. GitHub 우측 프로필 **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**을 엽니다.
2. **Resource owner: seionwon**, **Repository access → Only select repositories → HTMLMemo**를 선택합니다.
3. **Repository permissions → Contents: Read and write**, **Workflows: Read and write**를 부여합니다. 워크플로 파일을 업로드하므로 Workflows 권한도 필요합니다.
4. 토큰은 개발 도구의 자격 증명 저장소에서 사용합니다. 앱·설정 JSON·저장소·URL에는 넣지 않습니다. [GitHub 공식 토큰 생성 안내](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).

Pages의 게시 소스 설정은 위의 Settings 화면에서 한 번 진행합니다. 앱에는 GitHub 토큰 저장이나 업로드 API 기능을 추가하지 않습니다.

현재 개발 서버에서는 저장소에 지정된 seionwon 계정의 인증을 사용합니다. `gh auth status`의 전역 활성 계정이나 이전 실행 환경의 연결 오류만으로 게시가 불가능하다고 판단하지 않습니다. 관련 소스·검증·이력을 커밋한 뒤 `git push origin main`으로 기존 Actions 배포를 실행하고, 해당 커밋의 게시 성공과 온라인 파일 일치를 확인합니다. API 연결 오류와 localhost `listen EPERM`은 각각 현재 실행 환경에서 다시 확인합니다. 이 프로젝트의 작업 지침은 [AGENTS.md](AGENTS.md)에 있습니다.

## 개발 환경

Node.js 22 이상에서 검사와 빌드를 실행합니다.

```sh
npm ci
npm test
npm run check
npm run build
```

빌드 결과인 **dist/**는 GitHub Pages의 웹 루트로 게시할 정적 앱입니다. 빌드는 앱 전달용 ZIP이나 설치 안내 파일을 생성하지 않습니다. 실제 업로드와 Pages 게시에는 GitHub 인증과 저장소 설정이 필요합니다.

개발자가 서버 없이 코드를 검토할 때는 npm run dev로 생성된 public/HTMLMemo.html을 열 수 있습니다. 이 파일은 개발 검토용이며 사용자에게 전달하는 설치 파일이 아닙니다. 사용자 설치와 공유는 위의 Pages 주소로 진행합니다.

## Chrome에서 탐색하고 HTMLMemo에서 메모하기

**배포된 URL 하나만 열면 사용할 수 있습니다. 확장 기능·별도 프로그램·서버 연결은 사용하지 않습니다.** 앱 설치와 저장 폴더 연결은 선택 사항입니다.

주소창에 검색어나 URL을 넣고 Enter 또는 **브라우저에서 열기** 버튼을 누르면 외부 사이트는 Chrome의 일반 탭에서 바로 엽니다. 웹 페이지를 하나의 파일로 저장한 다음, HTMLMemo에서 열면 됩니다. 앱과 같은 출처의 예제 등만 앱 안에서 미리볼 수 있습니다.

- **전환과 복귀:** 앱에서 이미 연 주소를 다시 열거나 해당 웹 탭을 누르면 가능한 경우 기존 브라우저 탭으로 전환합니다. 전환만 할 때는 Chrome에서 이동한 검색 결과를 원래 주소로 다시 로딩하지 않습니다. 문서에서 검색·외부 링크를 열어도 읽던 문서와 주석은 유지합니다. 돌아오면 **글 붙여넣고 주석 달기** 또는 **HTML 파일 가져오기**를 이용합니다.
- **텍스트 붙여넣기:** 웹 탭의 전환 화면·앱 메뉴·**Ctrl/⌘ Shift V**(입력란 밖)로 엽니다. 복사한 글을 붙여넣고 제목과 선택적인 실제 원문 주소를 적으면 서재에 저장한 뒤 바로 주석을 남깁니다. 검색 URL을 실제 글의 주소처럼 저장하지 않도록 검색에서 시작한 원문 주소는 비워 둡니다. 최대 200,000자이며 실행 코드·이미지·원래 서식은 가져오지 않습니다. 클립보드나 다른 Chrome 탭의 본문·현재 주소를 자동으로 읽지 않습니다.
- **HTML 파일 가져오기:** HTML·HTM뿐 아니라 Chrome에서 단일 파일로 저장한 **MHTML·MHT**도 선택하거나 앱에 끌어다 놓습니다. MHTML 안의 본문·이미지·스타일·글꼴·저장된 프레임을 기기 안에서 풀어 보관하며 원래 사이트에 다시 접속하지 않습니다. 포함되지 않은 자료는 문서 정보에 표시합니다. MHTML은 저장 당시의 정적 문서로 열고 실행 코드는 실행하지 않습니다. 주석을 내보내면 자료와 주석을 포함한 단일 **HTML** 파일로 저장합니다. 원본 파일은 바꾸지 않습니다.
- **직접 저장은 선택 사항:** 외부 웹 탭의 **보낸 주소 · 직접 가져오기**를 펼치면 마지막으로 보낸 주소에서만 직접 읽기를 시도할 수 있습니다. 사이트가 CORS를 허용할 때만 가능하고 검색 페이지는 비활성화합니다. Chrome에서 나중에 이동한 페이지의 현재 화면을 캡처하는 기능이 아닙니다. 외부 프록시·서버·로그인 쿠키는 사용하지 않습니다.

탭 재사용은 현재 앱 실행 중에 직접 연 탭에 한정합니다. 앱 재시작·탭 닫힘이나 사이트의 COOP 격리 정책으로 연결이 끊기면 명시적으로 다시 열어야 하며 일반 Chrome 탭 전체를 검색하거나 제어하지 않습니다. 브라우저가 열기/초점 전환을 막으면 **보낸 주소**의 안전한 링크를 제공합니다. 외부 사이트로 보내기 전에 새 빈 탭의 `opener`를 끊어 앱 역방향 접근을 막고 리퍼러를 생략합니다. 앱 웹 탭을 닫아도 사용자가 탐색 중인 Chrome 탭을 닫지 않습니다. [창 열기와 브라우저 제약](https://developer.mozilla.org/en-US/docs/Web/API/Window/open).

붙여넣기와 직접 저장은 우선 이 기기의 앱 보관함에 저장하므로 파일 선택·폴더 연결이 필요하지 않습니다. 파일 사본이 필요할 때 **HTML 내보내기**를 사용합니다. 기존에 연결한 저장 폴더는 선택적으로 이용합니다. 직접 읽기 실패는 HTML/텍스트 가져오기로 이어지며 모든 사이트·로그인 화면·동적 콘텐츠의 완전한 보관을 보장하지 않습니다. 압축 책은 전체를 보존하도록 원본 HTML 가져오기를 안내합니다. 예전 확장 소스는 이력용으로 저장소에 남아 있으나 앱·오프라인 캐시·배포·다운로드에 포함하지 않습니다.

## 설정 파일

설정의 **설정 파일 저장**으로 테마·서재 정렬·주석 색상·굵기·투명도·펜 표시 시간·툴바 위치를 `HTMLMemo-settings.json`에 저장합니다. **설정 파일 불러오기**로 다시 적용할 수 있습니다. 파일 핸들을 연결한 경우 **다시 불러오기**는 같은 파일의 최신 내용을 읽습니다. 파일 선택 API를 지원하지 않는 경우에도 일반 파일 선택과 다운로드로 저장·복원을 사용할 수 있습니다.

잘못된 JSON, 다른 앱의 파일, 지원하지 않는 버전·값은 적용 전에 거부합니다. 설정 파일에는 문서나 파일 접근 권한을 넣지 않습니다. 저장 폴더 이름은 안내용으로만 보관하며, 다른 기기에서도 폴더 연결을 사용할 때만 다시 선택합니다. 다른 출처·브라우저의 보관함은 별도이므로 문서는 HTML 내보내기, 설정은 JSON으로 옮기세요.

**저장 폴더 연결**에서는 `문서/HTMLMemo` 또는 `다운로드/HTMLMemo` 같은 전용 하위 폴더를 선택하세요. 선택 창에서 폴더를 새로 만들 수 있습니다. 홈·문서·다운로드 폴더 전체와 시스템 폴더는 [Chrome의 접근 제한](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access#restricted-folders)에 걸릴 수 있습니다. 연결을 취소하거나 저장하지 못한 경우 기존 연결을 유지하고 다시 선택할 수 있습니다.

## 로컬 HTML과 주석

HTML 파일 선택, 파일 드래그, 서재에서 다시 열기 모두 동일한 주석 리더를 사용합니다. 원본 HTTPS 주소가 파일에 남아 있어도 로컬 문서 탭으로 처리합니다. 파일 쓰기 권한이 없어도 주석은 활성화됩니다.

문서를 열 때는 준비 안내를 표시하고, 주석 복원·확대 비율·읽기 위치·주석 좌표 배치를 마친 뒤 본문을 표시합니다. 이미 주석이 있는 파일의 보정 전 화면이 먼저 노출되지 않으며, 대용량 파일도 기존 Blob 방식으로 읽습니다.

상단의 HTML 파일 가져오기 아이콘 바로 왼쪽에 있는 책 모양 버튼으로 **내 서재**를 엽니다. 이름은 툴팁으로 표시하며, 서재가 열려 있을 때 버튼을 강조합니다.

여러 HTML 파일을 한 번에 선택하거나 차례로 열면 상단 한 줄의 **파일 탭**에 각각 표시됩니다. 탭을 눌러 문서를 바로 전환하고 `×`로 닫습니다. 전환 중에도 각 문서의 주석과 읽기 위치를 유지하며, 닫기는 저장을 마친 뒤 완료합니다. 탭이 화면보다 많으면 가로로 스크롤하고, 선택한 탭은 화면 안으로 이동합니다. 탭에서 좌우 방향키·Home·End로 전환하고 Delete로 닫을 수도 있습니다. 긴 제목과 파일 이름은 탭의 툴팁으로 확인합니다. 문서를 읽는 동안 주소창 자리에 탭을 표시하며 `Ctrl/⌘ L`로 주소를 입력하고 Esc로 파일 탭에 돌아옵니다.

한 줄 플로팅 툴바에서 선택·펜·형광펜·밑줄·지우개·메모를 사용할 수 있습니다. 색상·굵기·투명도 설정, 임시 펜, 실행 취소·다시 실행, 확대, 도형·화살표·영역 강조·취소선·텍스트, 검색, 목차·북마크, 주석은 버튼과 추가 도구 메뉴에서 엽니다. 손잡이를 드래그하면 툴바를 이동할 수 있습니다. 문서 내부 링크로 이동한 후 뒤로 버튼으로 출발 위치에 돌아갈 수 있습니다.

문서 자체에 목차 사이드바가 있으면 문서를 여는 순간 그 목차 위에 **목차 / 검색 / 주석**이 표시됩니다. 검색 입력란은 **불러온 부분에서 찾기**로 안내합니다. 검색·주석도 같은 사이드바에서 열리고, 목차로 돌아오면 원래 책의 트리·펼침 상태·스크롤 위치를 유지합니다. 검색어는 다른 보기로 갔다 돌아와도 유지하며, 주석 목록에서 해당 주석으로 이동하거나 삭제할 수 있습니다. 주석 목록의 각 줄에는 주석이 표시하거나 그려진 자리의 본문, 종류·그 위의 제목·만든 시각이 함께 나옵니다(메모는 메모 내용과 대상 문장). 문서 자체 목차가 없는 경우 추가 도구에서 앱의 오른쪽 패널을 열어 세 보기를 선택합니다. **추가 도구 → 목차 · 북마크**의 **현재 위치 저장**으로 북마크를 추가합니다. 앱이 삽입한 보기 선택 UI는 HTML 저장·내보내기 파일에 포함하지 않습니다.

문서 pane 오른쪽 위의 **전체 화면** 또는 **F**로 문서만 화면을 채우고, **전체 화면 종료** 또는 **Esc**로 돌아옵니다. 이 모드에서도 주석 툴바·주석 편집·자동 저장을 사용할 수 있습니다. 브라우저 전체 화면 API가 없거나 허용되지 않으면 앱 내부의 문서 전용 화면으로 전환합니다. 툴바의 기존 버튼·아이콘·순서·크기를 유지하면서 바깥 상하 여백은 0px, 좌우는 1px로 줄였으며 좁은 화면에서는 가로 스크롤로 모든 버튼에 접근합니다.

### 새 판으로 주석 옮기기

책이 고쳐져 새 HTML 파일(새 판)을 받으면, 지금까지 단 주석을 새 판으로 옮길 수 있습니다. 주석을 단 문서를 열고 **추가 도구 → 새 판으로 주석 옮기기**(또는 서재의 문서 메뉴)를 누른 뒤 새 판 파일을 고릅니다.

- 형광펜·밑줄·취소선과 문장에 단 메모는 **표시한 문장**을, 펜·도형·영역·텍스트는 **그려진 문단**을 새 판에서 찾습니다. 앞뒤 문장이 바뀌었거나 장이 옮겨졌어도 따라가고, 문장이 조금 고쳐졌으면 고쳐진 문장으로 옮깁니다(글자 기준 약 70% 이상 같을 때).
- MemoSuite 책(여러 장을 한 파일에 담은 책)은 장 ID로 같은 장을 먼저 찾고, 없으면 새 판 전체 본문에서 그 문장이 있는 장을 찾습니다. 새 판은 화면 밖에서 열어 주석이 있는 장만 그려 보므로 책 전체를 다시 읽지 않습니다.
- 새 판에서 문장(또는 문단)이 지워졌으면 그 주석은 옮기지 않습니다. 옮기기 전에 **그대로 있는 자리 / 고쳐졌거나 옮겨진 자리 / 지워진 내용** 개수와 옮기지 않는 주석 목록을 보여 줍니다. 위치 정보가 없는 예전 메모도 따로 표시합니다.
- **새 판 열기**를 누르면 새 판이 새 문서로 열리고 옮긴 주석이 자동 저장됩니다. 지금 문서와 그 주석은 서재에 그대로 남으므로, 결과를 확인한 뒤 필요 없으면 서재에서 지우면 됩니다. 북마크는 판마다 위치가 달라 옮기지 않습니다.
- 이 버전부터 책에서 새로 만드는 형광펜·밑줄·메모는 어느 장의 것인지도 기록해, 같은 문구가 다른 장에 있어도 그 장에만 표시되고 새 판에서도 바로 그 장을 찾습니다.

단축키: `V` 선택, `P` 펜, `H` 형광펜, `U` 밑줄, `E` 지우개, `N` 메모, `Ctrl/⌘ Z` 실행 취소, `Ctrl/⌘ Shift Z` 다시 실행, `Ctrl/⌘ F` 검색, `Ctrl/⌘ S` 저장, `Ctrl/⌘ L` 주소창. 읽던 위치와 확대 비율도 문서에 보관합니다.

## 자동 저장 위치

- **앱 보관함:** 가져온 HTML 본문은 보관하고, 주석·북마크·읽던 위치를 별도 메타데이터로 자동 저장합니다. 주석을 바꿀 때마다 본문을 다시 직렬화하거나 원본 파일을 쓰지 않습니다. 오프라인에서도 사용합니다.
- **원본 파일:** 읽기만 하며 자동 저장에 쓰기 권한을 요청하지 않습니다. 이전 버전에 연결했던 파일도 자동으로 덮어쓰지 않습니다.
- **휴지통:** 문서 메뉴 → **휴지통으로 이동**으로 본문·주석·북마크·저장 이력을 보관합니다. 내 서재의 **휴지통**을 누르고 문서를 선택해 **복원**하면 원래 폴더로 돌아갑니다. 원래 폴더가 삭제됐다면 최상위 폴더에 복원됩니다. 카드·목록 보기, 파일명·폴더 경로 검색, 삭제일 정렬을 사용하며 자동 삭제 기간은 없습니다. **영구 삭제**와 **휴지통 비우기**만 확인 후 되돌릴 수 없게 삭제합니다. 가져오기 전의 원본 파일은 지우지 않습니다.
- **저장 이력:** 추가 도구 → **주석 저장 이력** 또는 서재 문서 메뉴 → **주석 저장 이력**에서 저장 시점과 주석 내용을 확인하고 복원합니다. 주석·북마크가 달라진 저장 시점만 기록하며 스크롤·확대만으로는 이력을 늘리지 않습니다. 본문과 현재 읽던 위치는 유지하고 주석과 북마크만 복원하며, 복원 전 상태도 남아 복원을 되돌릴 수 있습니다.
- **내보내기:** **HTML 내보내기**로 현재 주석을 포함한 HTML 사본을 만듭니다. 기본 제안 이름에는 「-주석」을 붙입니다. 내보낸 파일은 이후 자동 갱신하지 않습니다. 페이지 저장·붙여넣기는 기본적으로 앱에 보관하며, 선택적으로 연결한 폴더가 있으면 생성 결과를 한 번 기록합니다.

주석과 이력은 하나의 IndexedDB 트랜잭션으로 함께 저장합니다. 실제 앱 저장 오류는 실패와 재시도 버튼으로 표시합니다. 이력에는 HTML 전체를 중복 저장하지 않고 주석과 북마크만 남깁니다. 기존 문서는 기능 적용 후 처음 열었을 때의 주석부터 기록하며, 이전 버전에서 보관하지 않았던 과거 이력은 생성할 수 없습니다. 이력은 자동 삭제하지 않으며 저장 공간이 부족하면 저장 실패로 알립니다.

주석·북마크 변경은 기존처럼 약 0.3초 뒤 저장합니다. 스크롤·확대 등 읽기 위치 변경은 멈춘 뒤 약 2초 후 모아 저장하며 `저장 중` 표시와 탭의 변경 표시를 켜지 않습니다. 위치가 같으면 다시 저장하지 않고, 위치만 저장할 때는 주석 이력·원본 본문·수정일을 변경하지 않습니다. 탭 닫기·앱을 벗어나기·수동 저장·내보내기에서는 마지막 위치를 바로 반영합니다. 실제 위치 저장 실패는 별도로 알리고 재시도할 수 있습니다.

이력은 해당 브라우저의 앱 보관함에 있으며 휴지통에서도 유지합니다. 전용 데이터 폴더를 연결하면 휴지통 상태·본문·주석·이력도 함께 자동 보관하므로 폴더 전체를 새 기기로 옮겨 복원할 수 있습니다. 휴지통의 영구 삭제·비우기 또는 브라우저 데이터 삭제는 앱 안의 이력도 삭제합니다. 중요한 상태는 전용 폴더 전체나 HTML 내보내기로 보관하세요. 내보내는 HTML에는 현재 주석이 포함되고 전체 이력은 포함되지 않습니다. 다른 기기의 HTMLMemo에서 열어 주석을 계속 편집할 수 있습니다.

문서 탭의 **×**를 누르면 주석과 읽던 위치의 저장이 완료된 뒤 닫힙니다. 실제 저장 오류가 있으면 탭을 유지합니다. 닫는 중인 문서를 서재에서 다시 열면 닫기가 완료된 뒤 보관한 주석을 불러옵니다.

서재는 문서 목록만 읽고 본문은 선택한 문서만 불러옵니다. 주석 자동 저장은 본문을 읽거나 다시 쓰지 않습니다. 큰 로컬 HTML은 원본 Blob을 보관하여, 압축 데이터를 펼친 DOM 전체를 저장용 문자열로 다시 만들지 않습니다. 이력 목록은 50개씩 표시하고 복원할 시점의 주석만 불러옵니다. 이력 미리보기는 최대 100개 주석·각 500자이며 실제 복원에는 모든 주석을 적용합니다.

## 지원 범위

웹앱은 다른 출처의 페이지 DOM이나 브라우저의 다른 탭에 임의로 접근할 수 없고, 프레임 표시가 금지된 사이트를 앱 안에 표시할 수 없습니다. 사이트가 허용한 CORS 직접 읽기만 시도하며 제한되면 일반 새 탭과 HTML/텍스트 가져오기를 사용합니다. 근거: [같은 출처 정책](https://developer.mozilla.org/en-US/docs/Web/Security/Same-origin_policy), [CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS), [X-Frame-Options](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Frame-Options).

웹 페이지 저장은 앱이 읽을 수 있는 현재 화면 또는 CORS가 허용된 HTML의 정적 스냅샷입니다. 원본 사이트의 실행 스크립트와 비밀번호 입력 값은 보관하지 않습니다. 스트리밍 영상·음원, 보호된 캔버스, 다른 출처의 외부 프레임, 아직 생성되지 않은 동적 콘텐츠는 완전히 보관할 수 없습니다. 리소스 하나는 25MB, 합계는 150MB로 제한하며, 빠진 리소스는 문서 정보에 표시합니다. 외부 CSS·이미지를 따로 참조하는 로컬 HTML은 해당 파일 하나만 선택하면 외부 파일을 함께 읽을 수 없으므로, 자체 포함 HTML을 권장합니다.

## 검증

```sh
npm install
npm run check
npm test
npm run build
```

단위·DOM 모델 검사는 로컬 파일 읽기, 읽기 전용 주석 경로, UTF 인코딩, 단일 파일 캡처, 주석 복원과 HTML 안전 처리, 편집 기록·동시 저장, 원본 수정 충돌·쓰기 실패, CORS 직접 읽기의 URL·인코딩·크기 제한과 안전한 텍스트 가져오기를 검사합니다. 추가로 네트워크 요청을 차단한 상태에서 실제 앱 스크립트를 실행해 설치 버튼의 일반 Chrome·iPhone 분기, 실행 탭의 URL 복사와 권한 실패 후 직접 복사 안내, 중복 복사 방지, 공개 웹 파일의 개인 데이터 제외와 오프라인 파일 목록·캐시 버전, 설정 저장·복원을 검사합니다. 실제 빌드에서 예전 확장 ZIP·브리지와 폐기한 배포 파일을 제외하고 dist/에 웹 앱만 생성하는지도 검사합니다. 예전 확장 소스의 안전성 회귀 검사는 소스 이력용으로 남아 있지만 앱에서 실행·게시하지 않습니다. DOM 모델 검사는 실제 Chrome 화면 렌더링 또는 OS 설치 검사가 아닙니다.

```sh
npm run test:browser
```

별도 Chrome 프로필과 localhost 테스트 서버로 웹 탐색 → 앱 보관함 저장 → 로컬 주석 → 명시적 HTML 내보내기 → 파일 가져오기 → 다시 열기 → 오프라인 흐름을 검사합니다. 확장 전송을 모의하지 않고 실제로 서로 다른 출처에서 CORS 허용·차단을 확인하며, 파일 선택 없이 붙여넣기·원문 주소 보존·스크립트 비실행·모바일 화면도 검사합니다. 공개 주소에서는 URL 단독 사용, 붙여넣기와 기존 목차·검색·주석·펜 검사를 실행합니다. macOS 에이전트에서는 Chrome을 직접 실행하지 않고 CodeMemo 검증 서비스와 CI를 사용합니다. 실행 가능한 환경에서 Chrome 경로를 지정할 때는 `CHROME_PATH`를 존중합니다. 실제 실행·게시 결과와 이전 실패 기록은 기능 이력에 보존합니다.


## 라이브러리 데스크 디자인

앱은 `public/design.tailwind.css`의 CSS-first `@theme`와 실제 HTML·JavaScript에서 사용하는 유틸리티를 Tailwind CSS **4.3.3**으로 로컬 컴파일합니다. `npm ci` 후 `npm run build` 또는 `npm run dev`를 실행하면 `public/styles.css`를 갱신합니다. 브라우저에서 Tailwind 런타임이나 CDN을 사용하지 않습니다. GitHub Actions도 같은 고정 버전 의존성과 빌드 단계를 사용합니다.

데스크톱에서는 왼쪽 서재 탐색 메뉴, 모바일에서는 상단에 줄바꿈되는 메뉴를 사용합니다. 기존 설정의 시스템·밝게·어둡게 선택을 유지합니다. SVG favicon과 앱 브랜드, 192·512px PWA 설치 아이콘에 새 문서 심볼을 적용했으며 단일 HTML에도 브랜드 아이콘을 포함합니다.

큰 로컬 HTML(4MiB 이상, UTF-8)은 File/Blob을 브라우저 리더에 먼저 전달하여 화면을 표시합니다. 전체 파일 문자열 읽기·별도 DOM 파싱·IndexedDB 저장을 먼저 기다리지 않습니다. 브라우저가 만든 DOM에서 주석 준비를 나눠 진행하고 완료 후 자동 저장합니다. UTF-16 등 다른 인코딩은 기존 인코딩 변환 경로를 유지합니다. 주석 툴바는 모든 버튼·아이콘을 유지하면서 세로 버튼 공간을 19px로 줄여, 테두리 포함 약 21px 높이를 사용합니다. 실제 대용량 파일의 Chrome 직접 열기와 동일한 소요 시간은 아직 검증하지 못했습니다.

주석을 복원할 때 기준 문단이 아직 없으면 문서 전체를 대신 사용하지 않고 해당 문단이 준비된 뒤 표시합니다. 압축 책은 첫 본문 생성까지 준비 화면을 유지합니다. 기존 파일의 기준 식별자를 보존하며 새 그리기 주석은 문단 식별자·본문 문맥·책 구간도 함께 보관하여 동적 문서의 번호 변경 후에도 같은 위치를 찾습니다.

로컬 HTML 파일 가져오기에서는 JavaScript와 이벤트 핸들러를 실행합니다. 내장 압축 데이터를 JavaScript로 펼치는 문서도 지원하도록 읽기 정책을 변경했으며, 늦게 생성된 본문에 주석 앵커를 추가하고 주석을 복원·자동 저장합니다. 실행 설정은 HTMLMemo 메타데이터에 기록되어 서재에서 다시 열 때 유지됩니다. 예전 버전에서 스크립트가 삭제된 보관본은 복구할 원본 코드가 없으므로 원본 HTML 파일을 다시 가져와야 합니다. 원본이 필요로 하는 외부 파일이나 자체 CSP, 특정 브라우저 API 제한까지 해제하는 기능은 아닙니다. 이번 변경의 실제 Chrome 통합 검증·Pages 게시 결과는 기능 이력에서 별도로 확인합니다.
