**목적:** 맥·윈도우·안드로이드·아이폰에서 같은 앱 주소와 Chrome, 같은 앱 설치 버튼으로 시작하도록 설치 안내를 단순화했습니다. GitHub Pages는 앱 코드를 제공하고 문서·주석·설정은 기기 안에 저장하도록 유지합니다.

**여는 위치와 사용법:** 화면 위의 **앱 설치** 또는 **실행 → 이 기기에 설치하기 → 앱 설치**를 누릅니다. 브라우저가 설치 이벤트를 제공하면 설치 창을 엽니다. 아이폰·아이패드는 Chrome의 **공유 → 홈 화면에 추가 → 추가** 순서를 안내합니다. iOS 16.4 이상과 최신 Chrome이 필요하며, 앱 버튼으로 iOS 공유 메뉴를 자동 실행하지 않습니다. 설치 후 앱 아이콘으로 열고 HTML 파일을 가져옵니다.

설치 창을 취소하거나 여는 데 실패하면 버튼을 다시 사용할 수 있습니다. 브라우저가 설치 이벤트를 제공하지 않으면 브라우저 메뉴에서 설치하는 방법을 표시합니다. 직접 연 HTML 파일과 확장 기능 페이지에는 PWA 설치가 가능한 앱 주소를 안내하며, 해당 파일의 읽기·주석 기능은 유지합니다. 설치 확인 이벤트 또는 앱 실행 모드가 확인될 때 설치 완료 상태를 표시합니다.

**전달 파일:** **실행 → 설치 안내 파일 저장**, 또는 실행 탭의 위쪽 **앱 내보내기**로 `HTMLMemo-install.html` 하나를 생성합니다. 파일에는 HTTPS 설치 주소와 안내만 들어가며, 문서·주석·설정·파일 권한·URL의 쿼리와 해시를 포함하지 않습니다. 파일 자체가 PWA 설치 프로그램은 아니므로 최초 설치에는 Pages 배포와 인터넷 연결이 필요합니다. 다운로드에 실패하면 오류를 표시하고 내보내기 버튼을 복구합니다.

**Pages 배포:** **실행 → 앱 소유자 · GitHub Pages 배포 파일 → Pages 배포 파일 저장** 또는 개발자 빌드로 `HTMLMemo-pages.zip`을 생성합니다. ZIP은 앱 파일만 포함한 `docs/` 폴더와 `.nojekyll`을 제공합니다. 저장소에 압축을 푼 docs 폴더를 업로드한 뒤 **Settings → Pages → Deploy from a branch → main → /docs → Save**를 사용합니다. 오프라인 준비에 필요한 파일을 포함하며, 앱 코드 변경 시 캐시 버전도 변경합니다. 같은 빌드를 다시 포장하면 캐시 버전은 유지합니다.

기본 예상 앱 주소는 `https://sweon.github.io/HTMLMemo/`입니다. 앱 사용과 위의 웹 업로드 절차에는 API 키가 필요 없습니다. GitHub API 업로드 자동화를 위한 선택 사항으로 저장소 하나에 대한 fine-grained 토큰의 Contents 읽기·쓰기 권한 설정 과정을 README에 기록했습니다. 앱에는 토큰 저장·GitHub API 업로드 기능을 추가하지 않았습니다.

**Chrome 연결:** 컴퓨터의 **Chrome 연결 → Chrome 연결 파일 저장**에서 확장 기능 ZIP을 받습니다. 기본 연결 대상을 sweon/HTMLMemo의 PWA로 설정하고 해당 프로젝트의 루트 및 index.html만 허용합니다. 같은 GitHub Pages 출처에 있는 다른 프로젝트와 무관한 사이트의 요청은 거부합니다. 캡처 전달과 주석 저장은 이 기기의 브라우저에서 처리합니다. 모바일 Chrome에서는 이 데스크톱 확장 기능을 설치할 수 없어 안내 화면에서 로컬 HTML 가져오기·주석·내보내기 범위를 설명합니다.

**검증:** `npm test` 66개 통과, 실패·취소·건너뛰기 0개. 설치 이벤트의 취소·오류·재시도, iOS 안내 분기, 설치 완료 확인, 직접 연 파일의 안내, 설치 안내 파일 다운로드와 실패 복구, Pages ZIP의 개인 데이터 제외와 캐시 갱신, 해당 Pages 프로젝트의 확장 연결 경계를 검증했습니다. 기존 로컬 HTML 주석·파일 저장 충돌·설정 JSON 저장과 복원 회귀 검사도 통과했습니다. `npm run check`에서 JavaScript 50개와 JSON 문법 검사 통과, `npm run build` 통과, `git diff --check` 통과. 실제 빌드의 Pages ZIP 24개 파일에 대해 CRC와 풀린 파일 바이트 일치를 확인하고, 설치 안내 HTML의 단일 HTTPS 목적지와 스크립트 부재 및 Chrome 연결 ZIP의 폴더 구조·CRC를 확인했습니다.

**배포 상태와 한계:** 이 작업에서는 GitHub 저장소 업로드나 Pages 활성화를 수행하지 않았습니다. 실제 네 플랫폼의 설치와 Chrome 확장 실사용 검증도 수행하지 않았습니다. 자동 검증은 단위 검사와 DOM·확장 메시지 모델 검사입니다. 설치 후 오프라인 사용은 브라우저 캐시가 유지되는 동안 가능하며, 웹 탐색에는 인터넷 연결이 필요합니다. 모바일의 모든 사이트 캡처와 외부 원본 HTML 자동 덮어쓰기를 지원한다고 주장하지 않습니다. 외부 파일 쓰기 API를 지원하지 않는 환경에서는 앱 내부 HTML에 자동 저장하고 HTML 내보내기로 외부 파일을 저장합니다.
