# PDFMemo 기능의 HTMLMemo 통합

HTMLMemo 1.3.0은 PDF에도 기존 HTML·마크다운의 읽기 툴바, 플로팅 주석 도구, 사이드바, 설정과 서재를 사용합니다. 별도 PDF 뷰어 화면이나 PDFMemo의 React·Android UI는 포함하지 않습니다.

PDFMemo의 `mobile/overrides/pdfTextSearch.ts`, `pdfEmbeddedSearchIndex.ts`, `PdfPageRendering.ts`, `pdfViewportWindow.ts`, `mobile/search-cache.ts`를 JavaScript로 옮겼습니다. 원본별 SHA-256과 이식 대상은 [provenance.json](../public/src/pdf/provenance.json)에 기록합니다. 원본 PDFMemo 프로젝트와 MemoSuite 공통 소스는 변경하지 않았습니다.

- 렌더링 대기열은 화면에 보이는 쪽의 자리를 남기고, 낮은 해상도 미리보기를 먼저 준비합니다. 화면 밖 래스터를 해제하며, 높이 900,000 CSS px의 이동 창으로 긴 문서의 스크롤 좌표를 관리합니다.
- 검색은 한글 띄어쓰기·호환 문자·합자를 정규화하고, 원문 색인과 선택한 결과의 좌표를 분리합니다. PDF에 들어 있는 MemoSuite 검색 색인을 우선 사용하며, 일반 PDF는 추출한 글자를 원본 바이트의 SHA-256별로 기기에 보관합니다. 색인은 파생 자료이며 원본이나 주석을 대체하지 않습니다.
- Android 전용 파일 부분 읽기는 로컬 Blob의 필요한 범위를 읽는 방식으로 연결했습니다. 서버·확장 프로그램·네이티브 앱을 요구하지 않습니다.
- PDF.js 6.4.299와 해당 worker·CMap·기본 글꼴·이미지 디코더를 로컬 자산으로 포함합니다. PDF 스크립트 실행 관리자와 QuickJS 실행 자산은 포함하지 않습니다. PDFMemo의 React UI나 예전 렌더러 바이너리를 복사하지 않습니다.
- HTMLMemo의 스크립트 없는 문서 iframe에서 처음 숨겨져 있던 캔버스가 표시되지 않는 Chrome 문제를 실제 검사에서 발견했습니다. 래스터 대기열과 픽셀 제한을 유지하면서 표시에는 해제 가능한 로컬 Blob 이미지를 사용합니다.

PDF의 주석·북마크는 원본과 분리해 기존 저장 이력·데이터 폴더·동기화·휴지통 경로를 사용합니다. 글자 표시에는 쪽 번호와 정규화한 사각형을, 그림에는 쪽 안의 상대 좌표를 기록합니다. A−·A+는 PDF의 고정 배치를 유지하며 페이지와 주석을 함께 조절합니다.

기존 “HTML 내보내기”를 세 형식에 공통으로 사용합니다. PDF를 내보내면 원본 PDF 바이트와 현재 주석·북마크를 하나의 `.html` 파일에 담습니다. 재가져오기 시 분할해서 디코딩하고 원본 바이트와 메타데이터를 검사합니다. 원본 PDF를 덮어쓰거나 일반 PDF 주석으로 다시 쓰지는 않습니다. 받는 분도 HTMLMemo의 파일 가져오기로 엽니다.

같은 PDF 원본이 서재에 있어도 새로 받은 공유 파일은 그 파일에 담긴 주석·북마크를 유지해 별도 문서로 가져옵니다. 이미 가져온 공유 파일과 바이트까지 같은 파일을 다시 가져올 때에만 기존의 세 가지 중복 선택을 표시합니다. PDF 원본 식별자는 검색·기기 동기화에서 계속 같은 값을 사용합니다.

스캔 이미지에는 OCR을 추가하지 않았습니다. 기존 PDF 주석은 원본의 표시를 유지하고, HTMLMemo에서 새로 단 주석을 편집합니다. 암호 파일은 해제한 사본이 필요하며 PDF 입력 양식·첨부 프로그램·Android APK 기능은 포함하지 않습니다. 새 판 이동은 본문을 확인한 항목을 옮기며, 중복 문구로 위치를 확정하지 못하는 경우 결과에서 제외하고 원래 문서를 유지합니다.

합성 PDF로 열기·선택·검색·주석·확대·공유 파일의 왕복을 검증합니다. 수만 쪽 위치 계산의 모델 검사는 실제 대용량 PDF나 실물 휴대폰 성능 검증과 구분합니다. 실제 검사·게시 결과는 [기능 추가 이력](<기능 추가 history.md#hist-20261031-003>)에서 확인합니다.
